# Problem Knowledge

This directory contains canonical knowledge about why SYNGAN exists, who needs it, what outcomes matter, and the scale envelope the design must eventually satisfy.

It describes the problem space without defining the final concept catalog or implementation architecture.

## Canonical documents

- [Problem & Purpose](problem-purpose.md) — motivating problem, product purpose, scope and non-goals.
- [Actors & Needs](actors.md) — actor roles and the needs that motivate the system.
- [Desired Outcomes](outcomes.md) — observable outcomes the design should make possible.
- [Enterprise Scale Envelope](enterprise-scale-envelope.md) — scale dimensions, design-center workloads and consequences that later design must address.

## Authority boundary

These documents are authoritative for the problem statements they own. They MUST NOT be read as authorization for a particular concept, class hierarchy, model family, distributed runtime, persistence format, or public API.

Implementation and representation choices remain downstream of concept discovery under [Design Methodology](../authority/design-methodology.md).
