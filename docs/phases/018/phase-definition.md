# Phase 018 — Implementation Execution Start Gate & Autonomous Delivery Qualification

## 017-F baseline

This is a durable high-level planning definition established by Phase 017-F.

It constrains a future start gate but does not authorize execution. Actual subphases and IPKG
manifests must be derived from then-current repository evidence after explicit human selection.

## Role

Establish the operational prerequisites and evidence needed before sustained product implementation can begin.

## Entry intent

Phase 017 complete and explicit human selection.

Selection authorizes only the bounded Phase 018 operational gate work. It does not imply that the
gate prerequisites are already satisfied.

## Start-gate PASS prerequisites

Before Phase 018 can PASS:

- protect main and enforce the required merge checks;
- reconcile all leftover planning branches against current main, preserving unique needed work and
  deleting only branches proven safe to remove;
- complete real tool-in-loop Cursor/Codex runtime qualification for the roles selected;
- confirm repository verification is passing;
- confirm no unresolved Class 3/4 conflict blocks the Phase 019 handoff.

## Required exit intent

Operational execution controls are proven and the Phase 019 start-gate inputs are ready, without implementing product capability.

Expected capability milestone: MVP-M0.

## Prospective package families

- none; this phase is gate/evaluation work rather than product-package execution

These are planning families, not package IDs or authorization sources.

## Non-goals

Product implementation, version bump, provider capability, public release, or automatic Phase 019 start.

## Authorization rule

Execution is NOT AUTHORIZED by this definition. Passing this phase never authorizes the next phase.
