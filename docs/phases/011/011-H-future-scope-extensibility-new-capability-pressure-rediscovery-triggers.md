## Classification discipline

Every future capability is classified as one of:

```text
F-1  fits existing concept unchanged
F-2  fits new state/action within existing purpose
F-3  requires new synchronization only
F-4  requires application-family capability refinement
F-5  requires genuine concept rediscovery
F-6  remains external authority / non-goal
F-7  insufficient evidence
```

A future concept is not accepted merely because rediscovery is foreseeable.

Rediscovery is triggered by an independent product-facing purpose with durable state/history, actions, lifecycle/invariants, reuse/cross-occurrence authority, and boundary pressure that cannot be owned cleanly by the current catalog.

## Key rediscovery rule

> **Genericity means accepting new instances within a stable purpose—not widening a concept until every future concern can fit inside it.**

A future capability must reopen discovery before implementation if otherwise it would require an existing concept to:

- gain an unrelated purpose;
- own another concept's state;
- absorb external organizational authority;
- become a generic infrastructure umbrella;
- preserve persistent cross-concept shadow state;
- or manage a new durable lifecycle meaningful independently of its current purpose.
