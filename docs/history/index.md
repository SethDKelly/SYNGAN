# Documentation History

## Purpose

Preserve design, architecture, implementation-planning, phase, audit, and reconciliation provenance without allowing historical detail to compete with current owners during ordinary retrieval.

History is evidence, not current authority.

## Rules

- Start ordinary work from `docs/index.md` and current section indexes.
- Enter history only for rationale, provenance, supersession analysis, or reconstruction.
- Historical `MUST`, `SHALL`, `canonical`, `active`, or `next` wording is stage-local unless re-adopted by current authority.
- Moving a file here does not erase or repudiate the decision; it changes its discovery role.

## History areas

- `phases/` — completed phase work records.
- `discovery/` — concept discovery, probes, candidate review, and validation evidence.
- `architecture/` — superseded/phase-generation architecture evidence.
- `authority/` — completed audits, consolidation and phase-specific authority evidence.
- `experience/` — prior consolidated experience contracts where current topic owners exist.
- `concepts/` — concept normalization/consolidation evidence.
- `synchronizations/` — prior synchronization refinement/consolidation evidence.
- `implementation/` — historical plans, completed slice authorities, and superseded implementation guidance.

The Phase 016 work record remains under `docs/phases/016/` while active.
