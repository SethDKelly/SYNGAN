# Archetypal, Exceptional & Progressive-Disclosure Misfit Replay

## Purpose

Establish the Phase 011-F authority for the **archetypal / exceptional component of G5** and the final Phase 011 disposition of:

```text
R010-05 — progressive-disclosure misfit
```

011-F asks:

> **When the complete mapped concept design is replayed as real conceptual histories rather than static structures, can ordinary interaction remain concise without hiding the limitation, uncertainty, historical orientation, optionality or semantic/operational distinction that changes the actor's immediate decision?**

Current answer:

```text
YES — ALL REQUIRED ARCHETYPAL AND EXCEPTIONAL REPLAYS REMAIN TRUTHFULLY EXPRESSIBLE,
      AND D0-D4 PROGRESSIVE DISCLOSURE CAN SIMPLIFY ENCOUNTER WITHOUT CONCEALING
      DECISION-MATERIAL SEMANTICS.
```

No concept, synchronization, application-family rule or Phase 010 mapping authority is reopened by 011-F.

`R010-05` is dispositioned **NO DEFECT**.

G5 is not finally closed because 011-G still owns adversarial, degraded, recovery, scale and provider-semantic-leakage stress.

# 1. Decision-material disclosure rule

011-F makes the following Phase 011 clarification explicit:

> **Progressive disclosure may defer explanatory depth, but it MUST NOT defer a qualifier whose omission could change the actor's immediate semantic decision or make a current state appear stronger than the owning concept supports.**

Therefore D0/D1 must carry, when material to the immediate decision:

```text
owner + semantic state
current actionability
candidate/non-final versus completed result
required limitation or uncertainty
current versus historical orientation
required Evidence strength/applicability
semantic versus operational completion distinction
continuity/recovery qualification that makes ordinary write action unsafe
capability absence when an actor might otherwise interpret it as failure
```

D2-D4 may defer detail such as:

```text
Attempt history
full Criterion/method explanation
full Provenance traversal
historical revision diff
large diagnostic material
host logs / metrics / traces
full distributed operational drill-down
```

This is a clarification of the existing Phase 010 D0/D1 contract, not a new state model, surface, API tier or mapping owner.

---

# 2. Replay method

For each required family/capability scenario, 011-F replays:

1. one **archetypal** history where the capability works normally;
2. one **material exceptional** history where a tempting simplification could produce a false interpretation;
3. the minimum decision-material facts required at D0/D1;
4. detail that may safely remain D2-D4;
5. a scenario-quality verdict.

A replay fails if truthful use requires a hidden concept, hidden coordinator, false mandatory capability, historical rewrite, stronger claim than the owner supports or representation-owned semantic truth.

# 3. Scenario replay matrix

## F-01 — authority-only definition / reuse

### Archetypal

An actor defines or selects an exact Data Meaning, Synthesis Strategy, Constraint or Evaluation Criterion revision and inspects its current-use status.

D0/D1 need only expose the authority owner, exact revision/current-use orientation and the immediate valid action.

No Learning, Generation, Evaluation, Execution or Provenance stage is implied.

**Result: PASS.**

### Exceptional

An older authority revision remains historically bound by prior work while a newer revision is current for new use.

D0/D1 for **new selection** must identify that the old revision is not the ordinary current choice. Historical inspection may still show that earlier work validly used it.

The design can show simultaneously:

```text
historical binding = revision v1
current authority = revision v2
v1 historical truth remains intact
```

No global `currentVersion` coordinator is required.

**SC-4 / SC-6: PASS.**

---

## F-02 — new Learning -> Learned State

### Archetypal

Learning commits against exact Data Meaning and Strategy, realizes work, completes semantically and establishes one primary Learned State.

D0/D1 can summarize:

```text
Learning completed
Learned State established
exact reusable result available
```

Execution/Attempt detail may remain D2/D4 unless operational diagnosis is immediately material.

**Result: PASS.**

### Exceptional

Operational work reaches an apparent endpoint but the intended reusable result cannot be validly established—for example only checkpoint/intermediate material exists or the semantic result fails its completion contract.

D0/D1 must not collapse this to `training completed` or `model ready`.

The truthful summary is equivalent to:

```text
Execution completed or stopped
Learning not semantically completed / result not established
no usable Learned State
```

Checkpoint and Attempt detail may remain deeper.

**SC-1 / SC-2 / SC-5: PASS.**

---

## F-03 — reuse existing Learned State -> Generation

### Archetypal

Generation selects an already-established usable Learned State, assesses contextual compatibility, commits the exact basis and completes without rerunning Learning.

D0/D1 must expose the selected Learned State and any material reuse limitation; producing Learning history may remain D3.

**Result: PASS.**

### Exceptional

The Learned State is restricted/retired/invalidated for current use while historical Generations remain bound to it.

For a **new Generation**, D0/D1 must foreground the current-use restriction strongly enough to prevent ordinary selection. Historical inspection may still show that earlier Generation G1 legitimately used the same exact Learned State before that status change.

The status change does not retroactively rewrite G1.

**SC-4 / SC-5: PASS.**

---

## F-04 — direct Generation

### Archetypal

A direct-capable Strategy generates without Learning/Learned State.

D0/D1 show the Generation request, direct synthesis basis, material Conditions/Constraints and current completion state.

No missing-model or skipped-training warning is required because Learning is absent by valid family design.

**Result: PASS.**

### Exceptional

Candidate material exists but a mandatory Condition or required completion check remains unresolved.

D0/D1 must distinguish:

```text
candidate material exists
Generation completed = no
required completion basis pending / not established
```

Physical output detail may remain deeper, but candidate existence cannot be summarized as completed Generation.

**SC-1 / SC-5 / SC-6: PASS.**

---

## F-05 — Evaluation-only use

### Archetypal

An Evaluation binds a Criterion, examines a stable subject and establishes interpretable Evidence. The Evidence may be favorable or unfavorable without changing the fact that the Evaluation validly completed.

D0/D1 must expose the Criterion/question orientation, finding and claim strength/limitation material to interpretation.

**Result: PASS.**

### Exceptional

The method completes computation but can support only an indeterminate, bounded or weaker claim than the Criterion ideally requested.

D0/D1 must not translate this to `passed`, `failed` or an unqualified metric value.

The truthful summary preserves:

```text
Evaluation completed as an examination
Evidence = indeterminate / bounded / limited at represented strength
stronger conclusion not established
```

Detailed method/uncertainty explanation may remain D2/D3, but the limitation itself cannot be deferred if it changes interpretation.

**SC-2 / SC-5: PASS.**

---

## F-06 — evidence-gated Generation

### Archetypal

Generation produces a stable candidate, Evaluation establishes completion-sufficient Evidence and Generation then completes through its own completion action.

D0/D1 may summarize the gate as satisfied while retaining the exact Evidence basis for deeper inspection.

**Result: PASS.**

### Exceptional

Evaluation completes successfully but Evidence is unfavorable or indeterminate for the mandatory completion requirement.

D0/D1 must preserve all three truths:

```text
Evaluation completed
Evidence unfavorable / indeterminate at represented strength
Generation not successfully completed under the committed gate
```

A provider job or Evaluation success badge cannot make Generation appear complete.

**SC-1 / SC-2 / SC-5: PASS.**

---

## F-07 — Constraint-aware Generation / Evaluation

### Archetypal

A Generation binds a reusable Constraint, records handling, and where necessary obtains completion-sufficient Evidence about the exact output/rule revision.

D0/D1 can show the applicable rule and whether its completion basis is established without requiring the actor to inspect the entire Evidence report.

**Result: PASS.**

### Exceptional

The Strategy declared handling=`enforced`, but later output-specific Evidence establishes a violation or remains indeterminate where determination is mandatory.

D0/D1 must not show `constraint enforced` as equivalent to `constraint satisfied`.

The truthful summary preserves:

```text
Constraint applicable
handling intent = enforced
satisfaction basis = violated / indeterminate
Generation completion affected accordingly
```

**SC-2 / SC-5: PASS.**

---

## F-08 — Execution-bearing long-running work

### Archetypal

A committed Learning, Generation or Evaluation is realized through Execution and one or more Attempts while the parent semantic owner remains independently inspectable.

D0/D1 may foreground parent semantic state plus a compact operational summary. Attempt detail belongs at D2/D4.

**Result: PASS.**

### Exceptional

A retryable Attempt fails, cancellation is requested but unresolved, or Execution reaches its operational endpoint while the parent still awaits semantic validation.

D0/D1 must preserve the decision-changing distinction, for example:

```text
Attempt failed — retry may remain valid
```

or

```text
Execution completed
Generation still awaiting required validation
```

or

```text
cancellation requested — terminal outcome not yet established
```

The actor does not need full host logs to avoid a false semantic conclusion.

**SC-1 / SC-2 / SC-5: PASS.**

---

## F-09 — Provenance-bearing historical explanation

### Archetypal

An actor traverses exact bindings and derivation relationships from authority through activity/result history.

D0/D1 may show a concise relationship summary; D3 may expose the full traversal.

Provenance does not become the owner of the referenced concept facts.

**Result: PASS.**

### Exceptional

A Provenance assertion is corrected/superseded, or retained history is partial/reconstructed.

The current explanation must distinguish the status/quality of the relationship assertion from the referenced concept truth. Missing history cannot be presented as proof that the event never occurred.

Where reconstruction/continuity uncertainty changes whether an actor may safely mutate current state, that qualification must be surfaced at D0/D1 rather than hidden in historical drill-down.

**SC-2 / SC-4 / SC-5: PASS.**

---

## F-10 — full-capability composition

### Archetypal

A capability-rich workflow may use reusable authority, Learned State, Generation, Constraint, Evaluation/Evidence, Execution and Provenance together.

The ordinary encounter remains task-centered rather than rendering eleven concepts as eleven mandatory stages.

D0/D1 expose the current owner/action, material basis and blockers. D2-D4 expose optional operational, Evidence, historical and host detail.

**Result: PASS.**

### Exceptional

The same history contains mixed states simultaneously, for example:

```text
Generation candidate exists
Execution operationally completed
required Evidence is indeterminate
older favorable Evidence exists but is now stale/inapplicable
Provenance history is available
Learning is not part of this invocation because an existing Learned State was reused
```

The design can represent all of these without a global `Workflow.status`, `Validation.status` or `Overall.status`.

D0/D1 must foreground only the facts that change the immediate Generation decision:

```text
Generation not completed
required current Evidence insufficient/indeterminate
existing Learned State reuse is the committed basis
```

The stale historical Evidence and deeper Provenance/Execution detail remain inspectable without taking over the current decision.

**SC-1 through SC-6: PASS.**

# 4. Progressive-disclosure concealment matrix

011-F explicitly tests the six concealment risks required by the Phase 011 decomposition.

| Risk | D0/D1 requirement | Deferrable detail | Result |
|---|---|---|---|
| material limitations | state the limitation when it changes commitment/use/completion | full rationale / supporting diagnostics | PASS |
| Evidence strength / uncertainty | state bounded/statistical/indeterminate nature when interpretation depends on it | method detail, confidence derivation, diagnostic corpus | PASS |
| current vs historical status | identify orientation when current action differs from historical use | full revision diff/history | PASS |
| authority-continuity uncertainty | block/qualify ordinary write action when continuity is not established | reconciliation details / platform evidence | PASS baseline; stress in 011-G |
| optional capability absence vs failure | omit absent capability or label not-applicable where needed | explanation of broader capability family | PASS |
| semantic vs operational completion | foreground distinction whenever one could be mistaken for the other | Attempt/platform drill-down | PASS |

No concealment risk requires a new concept, mapping owner or universal status.
